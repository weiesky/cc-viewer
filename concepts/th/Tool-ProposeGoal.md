# ProposeGoal

เสนอเป้าหมายความสำเร็จที่ตรวจสอบได้สำหรับเซสชัน เป้าหมายจะแสดงให้ผู้ใช้เห็นใน dialog อนุมัติ (โดยค่าเริ่มต้น) และเมื่อตั้งแล้วจะชี้นำ conversation ที่เหลือไปสู่ผลลัพธ์ที่ตรวจสอบได้

## เมื่อใดควรใช้

- เซสชันมีสถานะสิ้นสุดที่ชัดเจนซึ่งผู้ประเมินสามารถตรวจสอบได้จาก conversation (เช่น "all tests in test/auth pass")
- คุณต้องการให้ผู้ใช้ลงนามยอมรับอย่างชัดเจนว่า "เสร็จ" หมายความว่าอะไรก่อนลงมือทำงานใหญ่
- คำพูดของผู้ใช้เองระบุผลลัพธ์ไว้แล้ว และคุณต้องการบันทึกเป็นเป้าหมายของเซสชัน

## การเปิดใช้งาน

- ปิดตามค่าเริ่มต้น (feature flag ฝั่ง server)
- ถูกแยกออกจากเซสชันแบบ interactive และ background
- ปิดโดย settings key `modelProposedGoals: "disabled"`

## พารามิเตอร์

- `condition` (string, required): เงื่อนไขความสำเร็จ เขียนในลักษณะที่ผู้ประเมินอีกคนสามารถตรวจสอบได้จาก conversation (เช่น "all tests in test/auth pass (bun test exits 0)") ความยาวไม่เกิน 500 ตัวอักษร — ผู้ใช้ต้องอ่านเงื่อนไขทั้งหมดใน dialog อนุมัติได้
- `ask_user` (boolean, optional): จะถามผู้ใช้เพื่ออนุมัติก่อนตั้งเป้าหมายหรือไม่ ค่าเริ่มต้นคือ true (แสดง dialog อนุมัติ) ตั้งเป็น false เฉพาะเมื่อคำพูดของผู้ใช้เองใน conversation นี้ระบุผลลัพธ์นี้ว่าเป็นสิ่งที่ต้องการเท่านั้น เป้าหมายจะถูกตั้งโดยตรงพร้อมข้อความแจ้งที่มองเห็นได้ และผู้ใช้ล้างได้ด้วย `/goal clear`

## ตัวอย่าง

### ตัวอย่างที่ 1: เสนอเป้าหมายที่มี test รองรับ

```
ProposeGoal(condition="npm run test exits 0 with the new catalog cases included")
```

ผู้ใช้เห็นเงื่อนไขใน dialog อนุมัติ และยอมรับ, แก้ไข, หรือปฏิเสธได้

### ตัวอย่างที่ 2: รับผลลัพธ์ที่ผู้ใช้ระบุไว้โดยตรง

```
ProposeGoal(condition="the login form validates email format and shows an inline error", ask_user=false)
```

ใช้ได้ก็ต่อเมื่อผู้ใช้ระบุผลลัพธ์นั้นอย่างชัดเจนก่อนหน้าใน conversation เท่านั้น

## หมายเหตุ

- ทำให้ `condition` สั้นและตรวจสอบได้อย่างเป็นรูปธรรม — เป้าหมายที่คลุมเครือ ("make it better") ทำให้จุดประสงค์เสียไป
- `ask_user=false` จำกัดเฉพาะผลลัพธ์ที่ผู้ใช้ระบุเองเท่านั้น นอกเหนือจากนั้นต้องผ่าน dialog อนุมัติ
