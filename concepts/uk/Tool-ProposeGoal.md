# ProposeGoal

Пропонує перевірювану мету завершення для сесії. Мета показується користувачу в діалозі затвердження (за замовчуванням) і, щойно встановлена, спрямовує решту розмови до результату, який можна перевірити.

## Коли використовувати

- Сесія має конкретний кінцевий стан, який оцінювач міг би перевірити з розмови (наприклад, "all tests in test/auth pass").
- Ви хочете отримати явне підтвердження користувача щодо того, що означає «готово», перш ніж виконувати значну роботу.
- Слова самого користувача вже сформулювали результат, і ви хочете зафіксувати його як мету сесії.

## Активація

- Вимкнено за замовчуванням (серверний функціональний прапорець).
- Виключено з інтерактивних і фонових сесій.
- Вимкнено ключем налаштувань `modelProposedGoals: "disabled"`.

## Параметри

- `condition` (string, обовʼязковий): Умова завершення, сформульована так, щоб окремий оцінювач міг перевірити її з розмови (наприклад, "all tests in test/auth pass (bun test exits 0)"). Не більше 500 символів — користувач має мати змогу прочитати всю умову в діалозі затвердження.
- `ask_user` (boolean, необовʼязковий): Чи запитувати у користувача затвердження перед встановленням мети. За замовчуванням true (показується діалог затвердження). Встановлюйте false ЛИШЕ тоді, коли слова самого користувача в цій розмові сформулювали цей результат як бажаний; мету тоді встановлюється безпосередньо з видимим повідомленням, і користувач може очистити її командою `/goal clear`.

## Приклади

### Приклад 1: Пропозиція мети, підкріпленої тестами

```
ProposeGoal(condition="npm run test exits 0 with the new catalog cases included")
```

Користувач бачить умову в діалозі затвердження і може прийняти, відредагувати чи відхилити її.

### Приклад 2: Безпосереднє прийняття сформульованого користувачем результату

```
ProposeGoal(condition="the login form validates email format and shows an inline error", ask_user=false)
```

Допустимо лише тому, що користувач явно сформулював цей результат раніше в розмові.

## Примітки

- Тримайте `condition` короткою й обʼєктивно перевірюваною — розпливчасті цілі ("make it better") зводять призначення нанівець.
- `ask_user=false` суворо обмежено результатами, які сформулював сам користувач; усе інше має проходити через діалог затвердження.
