# SendUserMessage

Надсилає повідомлення користувачу — основний видимий канал виводу в сесіях у стилі brief. Відомий також під застарілим псевдонімом `Brief`.

## Коли використовувати

- Відповідь на щойно сказане користувачем (`status="normal"`).
- Проактивний показ чогось, чого користувач не просив і що йому потрібно побачити зараз — завдання завершується, поки він відсутній, блокатор, на який ви натрапили, непрохане оновлення статусу (`status="proactive"`).

## Параметри

У brief-режимі:

- `message` (string, обовʼязковий): Повідомлення для користувача. Підтримує форматування markdown.
- `attachments` (array, необовʼязковий): Вкладення, показані поруч із повідомленням. Кожен запис — або шлях файлу (абсолютний або відносний до cwd) для локально читаного файлу, або попередньо розвʼязаний обʼєкт `{file_uuid, file_name, size, is_image}`, отриманий від інструмента пристрою, такого як `attach_file`.
- `status` (string, обовʼязковий): `proactive` для непроханих оновлень, які потрібні користувачу зараз; `normal`, коли відповідаєте користувачу.

У збірках без brief доступний лише `message`.

## Приклади

### Приклад 1: Проактивне сповіщення про завершення

```
SendUserMessage(
  message="The migration finished — 42 files updated, tests green.",
  status="proactive"
)
```

## Примітки

- Увімкнено лише в brief-режимі або через відповідне поступове впровадження функції; більшість інтерактивних CLI-сесій натомість розмовляють з користувачем напряму.
- Використовуйте `proactive` економно — він призначений для речей, які справді потребують уваги користувача зараз.
