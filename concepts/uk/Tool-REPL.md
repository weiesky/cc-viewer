# REPL

Виконує JavaScript у постійному vm-контексті Node.js всередині сесії. Підтримується top-level `await`, а змінні/функції, визначені в одному виклику, залишаються доступними в пізніших викликах.

## Коли використовувати

- Швидкі обчислення, перетворення даних або опрацювання JSON, які простіші в коді, ніж в однострочниках shell.
- Багатокрокові скрипти, де проміжний стан має зберігатися між викликами (лічильники, накопичені результати).
- Інтерактивне дослідження поведінки API чи бібліотеки перед записом її у файл.

## Параметри

- `code` (string, обовʼязковий): JavaScript-код для виконання. Підтримує top-level await. Стан зберігається між викликами.
- `description` (string, необовʼязковий): Чіткий, лаконічний опис того, що робить цей скрипт, в активному стані (5–10 слів), наприклад "Trace upgrade message to its GrowthBook flag".
- `timeout` (number, необовʼязковий): Тайм-аут у мілісекундах. За замовчуванням — 30000; максимум 600000.

## Приклади

### Приклад 1: Обчислення та повторне використання стану

```
REPL(code="const counts = new Map(); ['a','b','a'].forEach(k => counts.set(k, (counts.get(k)||0)+1)); counts.get('a')")
```

Повертає `2`; `counts` залишається визначеним для наступних викликів REPL у тій самій сесії.

### Приклад 2: Top-level await з довшим тайм-аутом

```
REPL(
  code="const res = await fetch('https://example.com/api'); await res.json()",
  description="Fetch example API and parse JSON",
  timeout=60000
)
```

## Примітки

- Стан є по-сесійним: перезапуск сесії очищає всі визначення.
- Це середовище JavaScript (Node) — використовуйте Bash для shell-команд, роботи з файловою системою чи середовищ не-JS.
- Тривалому коду слід задавати явний `timeout`; типові 30 с убивають усе повільніше.
