# REPL

Выполняет JavaScript в постоянном vm-контексте Node.js внутри сессии. Поддерживается верхнеуровневый `await`, а переменные/функции, определённые в одном вызове, остаются доступными в последующих вызовах.

## Когда использовать

- Быстрые вычисления, трансформация данных или обработка JSON, которые проще сделать в коде, чем в shell-однострочниках.
- Многошаговые скрипты, где промежуточное состояние должно сохраняться между вызовами (счётчики, накопленные результаты).
- Интерактивное исследование поведения API или библиотеки перед записью его в файл.

## Активация

- Выключен по умолчанию — задайте `CLAUDE_CODE_REPL=true`, чтобы включить его.
- В терминальных (`cli`) и claude.ai (`remote`) сессиях серверный фича-флаг также может включить его.
- Когда выключен, REPL скрыт из списка инструментов модели. Когда включён, `Read`, `Glob`, `Grep`, `Bash`, `PowerShell` и `NotebookEdit` заменяются сокращениями REPL.

## Параметры

- `code` (string, обязательный): JavaScript-код для выполнения. Поддерживает верхнеуровневый await. Состояние сохраняется между вызовами.
- `description` (string, необязательный): ясное, краткое описание того, что делает скрипт, в действительном залоге (5–10 слов), например "Trace upgrade message to its GrowthBook flag".
- `timeout` (number, необязательный): таймаут в миллисекундах. По умолчанию 30000; максимум 600000.

## Примеры

### Пример 1: вычисление с повторным использованием состояния

```
REPL(code="const counts = new Map(); ['a','b','a'].forEach(k => counts.set(k, (counts.get(k)||0)+1)); counts.get('a')")
```

Возвращает `2`; `counts` остаётся определённым для последующих вызовов REPL в той же сессии.

### Пример 2: верхнеуровневый await с увеличенным таймаутом

```
REPL(
  code="const res = await fetch('https://example.com/api'); await res.json()",
  description="Fetch example API and parse JSON",
  timeout=60000
)
```

## Примечания

- Состояние привязано к сессии: перезапуск сессии очищает все определения.
- Это среда JavaScript (Node) — используйте Bash для команд shell, тяжёлой работы с файловой системой или не-JS рантаймов.
- Долго выполняющийся код должен задавать явный `timeout`; стандартные 30 с прерывают всё, что медленнее.
