feat(server): run IM workers (DingTalk/Feishu/WeCom/Discord) on the Claude Agent SDK instead of a node-pty-spawned `claude` CLI. The worker entry is now `ccv --im-sdk <id>` (bare `--im <id>` is kept as an alias so an older main ccv still lands on the SDK path after upgrade, and `--im-pty` remains as a hidden legacy escape hatch), booting `runImSdkMode`: same per-platform lock, `IM_<id>/` working directory, `CC_APPEND_SYSTEM.md` persona, built-in skills, 7050-7099 loopback port range and `CCV_IM_DENY=1`, but the session is a headless SDK query, so the first-run trust/bypass dialogs can no longer hang an unattended bot. The IM bridge gained optional headless deps (`sendPrompt`/`interrupt`/`isSessionAvailable`/`getReplyText`); turn-end replies use the interceptor live text with the SDK result text as fallback. Permission enforcement under `bypassPermissions`: the CLI shadows `canUseTool` in that mode (CLAUDE_SDK_CAN_USE_TOOL_SHADOWED), so the IM worker's authoritative enforcement layer is an in-process `PreToolUse` hook mounted by sdk-manager — it hard-denies the IM rule set (credential reads incl. Grep/Glob/NotebookRead, exfil/escalation Bash) and, for an unattended worker, also denies the interactive tools (AskUserQuestion/ExitPlanMode) and publish so nothing parks waiting on a human. Lock/liveness probing in the worker process manager is unchanged.
