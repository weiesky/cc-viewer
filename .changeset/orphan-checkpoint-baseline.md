**fix(logs): interrupted requests no longer freeze the offline/live conversation view (queued user prompts invisible).** An interrupted request (Esc/Stop, or the queue bubble's "Send now") never receives a `done` record, so its synthesized entries keep `inProgress` forever. The delta reconstructors skipped ALL `inProgress` rows — including checkpoint-shaped placeholders carrying the authoritative full conversation state — so the baseline lagged, the next completed delta failed its `_totalMessageCount` integrity check, and the poisoned freeze hid the ENTIRE rest of the session in the log-file view (queued follow-up prompts included). All three reconstruction APIs (`reconstructEntries`, `reconstructSegment`, `createIncrementalReconstructor` — covering the offline ingest, the client live SSE lane, and the server watcher/live-feed rebuilds) now absorb placeholder CHECKPOINTS into the baseline without touching the seq guard (a later completed twin at the same `_seq` still applies; re-applying a checkpoint is idempotent); placeholder DELTAS stay excluded (their twin may still re-deliver the same slice). Regression tests: batch absorb + integrity, stale-order/same-seq placeholder non-rewind, non-delta placeholder exclusion, segment-level absorb, and incremental baseline update with unchanged display semantics.
