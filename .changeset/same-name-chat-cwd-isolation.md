fix(multi-project): the chat panel now follows the viewed instance's project when two same-basename projects run from different directories. ccv stamps each new session dir's `meta.json` with its owning full `cwd` (from the `x-ccv-project-dir` self-report, normalized lexically — no realpath), and the `/events` cold-load fallback is scoped to the viewed instance's cwd (resolved from its live PTY record) instead of serving the newest content-bearing session from the whole shared basename pool. Same-cwd twin collaboration is unaffected (same cwd always matches); a legacy session with no `meta.cwd` stays eligible (never mis-excluded into a `sid-not-found`); a dead instance (no live record) conservatively degrades to today's whole-pool behavior. Forward-looking: only sessions created after this change carry `meta.cwd`, so pre-existing cross-dir history may still be served to either view until those sessions age out. Two further open (fail-open, never mis-excluding) gaps, out of scope here: an in-terminal `/cd` has no live hook to update the PTY record's `s.cwd`, so a post-`cd` session is stamped with the new cwd while `targetCwd` still resolves to the original spawn cwd (degrades to the old cross-project serve); and a `?project=` view with no `?instance=` is intentionally not cwd-filtered (exactly the pre-change behavior). Coverage: `v2-session-select.test.js`, `v2-layout-normalize-cwd.test.js`, `events-samename-cwd.test.js`.
