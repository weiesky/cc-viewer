fix(multi-project): all view-scoped READ panels (file tree / skills / git status+repos / expert / search / file content) no longer return HTTP 400 "ambiguous project name" on the BOUND view when two same-basename projects run at once. A new module-level view-scope singleton (`utils/viewScope.js`, mirrored from App state each update) is now the single source of truth, and `withViewParams` falls back to its instance when the caller passes none — so every view-scoped read disambiguates the two same-name projects centrally, instead of threading `instance` per call site. The same bound-instance fallback is applied to the remaining bare-`viewedInstance` channels: the terminal WebSocket handshake (`TerminalWsProvider`) and the resume-session POST, which would otherwise attach the wrong same-name twin / 409 "ambiguous". The project-stats / proxy-stats presence oracles are routed through the same helper too (their data stays name-shared; only the oracle needs the disambiguator). Also fixed: the request-detail fetch built its `v2:<project>/<sid>` token from the BOUND `projectName` instead of the viewed project, so opening a request from a viewed (parallel/same-name) project 404'd `/api/v2-entry` when viewed ≠ bound — it now uses the viewed project. MobileGitDiff's hand-built `?project=` is routed through the same helper. Mobile is a documented boundary (no bound-instance fallback; predominantly single-project). Also removes the temporary `[ccv-dbg]` debug logging from `resume.js`. Coverage: `view-scope.test.js`, `resume-route.test.js`.
