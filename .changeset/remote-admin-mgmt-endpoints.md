fix(server): allow authenticated remote admins to use management endpoints (container/cloud deployment). Previously every management route was hard-gated on `isLocal` (loopback socket peer), which assumes the admin sits on the host machine. In a single-container or cloud deployment the admin's browser is remote, so configuring the DingTalk/IM integration failed with "保存失败: Loopback only", and the start flow reported "启动失败: worker 未在限定时间内就绪" because the status poll never received the `process` field.

`decideAuth` (the single auth decision function in `lib/auth.js`) now also returns an `isAdmin` flag computed from the credential-bearing allow branches (loopback / valid `?token=` / valid password-login cookie) — so the elevation can never drift from the gate. Empty-password mode is deliberately NOT admin: it grants read access but keeps destructive/admin actions credential-or-loopback gated, so an open instance can't be hijacked by every network client. `server.js` attaches `isAdmin` as `req.ccvIsAdmin`. Management routes (`im`, `dingtalk`, `auth`, `project-prefs`, `preferences`, `skills`, `voice-pack`) accept `isAdminReq(req, isLocal)` instead of a bare `isLocal` check. The IM/DingTalk `status` endpoint now returns the full `process`/`pid`/`connection` (including `lastError`, so the header chip can render the real connection error) to an authenticated remote admin; only the plaintext secrets stay loopback-only. `/api/preferences` also returns a `_isAdmin` flag (and emits `_projectPrefsKeys` to a remote admin) so the admin-only settings UI shows for a remote admin, not just for loopback — the frontend (`AppHeader.jsx` desktop + `Mobile.jsx`) now gates the project-prefs management entry and the Claude executable selector on `preferences._isAdmin` instead of the loopback-only `_isLocal`. The internal machine bridges (hook notifies in `events.js`, `streamChunk` in `ask-perm.js`) remain strictly loopback + `INTERNAL_TOKEN` — they are not relaxed by `isAdmin`. The IM worker still binds `127.0.0.1` (single-container loopback probe is unaffected). No listen-address, port, or `CCV_HOST` behavior changed.

Coverage: `is-admin.test.js` (new), `auth-lib.test.js` (decideAuth isAdmin branches), `branch-routes-im.test.js` (remote-admin status/config + secret/lastError non-exposure), `api-dingtalk-gap.test.js` (DingTalk remote-admin status/config/test tiering), `task-event-route.test.js` (B-class bridges stay loopback-locked even with a valid token).
