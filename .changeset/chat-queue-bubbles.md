**Busy-queue floating bubbles with "Send now" for the chat composer (SDK mode + terminal-hidden mode).** Pressing Enter while Claude is running now queues the message server-side instead of silently swallowing it into an invisible queue: the queue is broadcast over the terminal WS (`queue-state`, replayed on reconnect) and rendered as floating bubbles stacked above the composer, each with a **Send now** button (interrupts the current run and injects that message immediately — Claude Code's native "Esc keeps what you queued and sends it right away" parity) and a remove (×) button. SDK mode: `sdk-manager`'s previously invisible `_messageQueue` becomes id-addressable `{id,text,ts}` items with broadcast-on-mutation, a shared `_interruptActiveQuery` core, and `sendQueuedNow`/`removeQueued`/`clearQueued`/`getQueueSnapshot` exports. PTY mode: new `server/lib/chat-queue.js` module (dependency-injected, unit-tested without node-pty) holds the queue and injects via the IM bridge's proven bracketed-paste path, gated on streaming state, pending approvals, PTY kind (never injects into a bare shell), and IM-injection mutual exclusion; a poll timeout never blind-injects (a mistimed paste could answer a TUI-native question prompt), it re-parks the item instead; a full queue negatively acks (`queue-rejected` → in-app toast) so an optimistically-cleared composer never loses a draft silently. Stop keeps queued bubbles parked (suppress-drain until a new turn starts); session/workspace switches clear the queue on both sides. New i18n keys `ui.chatInput.queueSendNow`/`queueRemove`/`queueHint`/`queueFull` × 18 locales.
