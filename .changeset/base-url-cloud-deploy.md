feat(server): add `CCV_BASE_URL` for cloud reverse-proxy deployment — one env var accepts `host/path`, `/path`, `scheme://host/path`, or protocol-relative `//host/path` (ws/wss normalized to http/https). The extracted path prefix drives the existing base-path machinery (HTTP/WS prefix strip, `<base href>` + `window.__CCV_BASE_PATH__` injection, plugin mounts, startup/QR URLs), matching both literal `{token}` segments and their percent-encoded request forms; the bare prefix (no trailing slash) now serves the app root (`/`). When a host is present it is merged into the Host allowlist and used to build external links (startup `External:` line, browser auto-open, `/api/local-url` QR link) with scheme resolution: explicit > `X-Forwarded-Proto` > default `https`, always carrying ccv's own `?token=`. `CCV_BASE_URL` takes precedence over `CCV_BASE_PATH`; invalid values fall back with a warning (4 new i18n keys × 18 locales). Also fixes: the password login page posting to an unprefixed endpoint behind a prefix-preserving proxy, i18n interpolation re-substituting a `{token}` path segment with the access token, and plugin cookie `Path` now uses the wire-encoded prefix. Docs: `docs/base-url.md` / `docs/base-url.zh.md`.
