## 1.8.0

### Minor Changes

- dafe2bc: **Busy-queue floating bubbles with "Send now" for the chat composer (SDK mode + terminal-hidden mode).** Pressing Enter while Claude is running now queues the message server-side instead of silently swallowing it into an invisible queue: the queue is broadcast over the terminal WS (`queue-state`, replayed on reconnect) and rendered as floating bubbles stacked above the composer, each with a **Send now** button (interrupts the current run and injects that message immediately — Claude Code's native "Esc keeps what you queued and sends it right away" parity) and a remove (×) button. SDK mode: `sdk-manager`'s previously invisible `_messageQueue` becomes id-addressable `{id,text,ts}` items with broadcast-on-mutation, a shared `_interruptActiveQuery` core, and `sendQueuedNow`/`removeQueued`/`clearQueued`/`getQueueSnapshot` exports. PTY mode: new `server/lib/chat-queue.js` module (dependency-injected, unit-tested without node-pty) holds the queue and injects via the IM bridge's proven bracketed-paste path, gated on streaming state, pending approvals, PTY kind (never injects into a bare shell), and IM-injection mutual exclusion; a poll timeout never blind-injects (a mistimed paste could answer a TUI-native question prompt), it re-parks the item instead; a full queue negatively acks (`queue-rejected` → in-app toast) so an optimistically-cleared composer never loses a draft silently. Stop keeps queued bubbles parked (suppress-drain until a new turn starts); session/workspace switches clear the queue on both sides. New i18n keys `ui.chatInput.queueSendNow`/`queueRemove`/`queueHint`/`queueFull` × 18 locales.
- efc7f8e: `ccv -SDK` headless mode now shares the full PTY-mode surface: SDK launches run a headless `claude` subprocess through the same observation plane (loopback proxy + fetch hook + wire-format v2 storage + SSE streaming/typewriter), with synthetic display entries retired from the sdk-manager. Tool approvals (Bash/Edit/Write/NotebookEdit/WebFetch/WebSearch) ride `canUseTool` into the Web UI with allow/deny/allow-for-session; `AskUserQuestion` and `ExitPlanMode` use the same modal flow. A shared `server/lib/approval-policy.js` keeps the IM deny short-circuit (`CCV_IM_DENY`) and the npm-publish hard gate (forced approval even under `--d`) identical across both modes. The terminal WebSocket now connects in SDK mode too (user messages, approval answers, interrupt), query failures surface as an in-app toast, pending approvals survive a WS disconnect via connection replay (PTY perm hooks included), typing `/` shows the session's slash-command hint, and compaction boundaries render as a system notice. Launch args `--model`/`-c`/`-r <id>`/`--fork-session` map to native SDK options (spawn config extracted into shared `server/lib/launch-config.js`, consumed by both PTY and SDK launches with resume-pinned system prompts). Falls back to PTY mode when the Agent SDK is unavailable.
