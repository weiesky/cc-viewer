When adding new interactive controls, remember to add corresponding i18n entries. The project has two separate i18n files: `src/i18n.js` (frontend/React components) and `server/i18n.js` (server-side/CLI). Add keys to the correct file based on where the translation is used.
After completing any code changes, automatically run `pnpm run build` to rebuild the project.
The repo uses pnpm (pinned via the `packageManager` field; settings in `pnpm-workspace.yaml`): install dependencies with `pnpm install`, and never commit `package-lock.json`. Dev toolchain floor is Node >=22.13 (pnpm 11 hard-requires it; CI uses Node 24). Corepack is bundled with Node <=24 and auto-provisions the pinned pnpm; on Node >=25 (Corepack removed) install it with `npm i -g pnpm@11.22.0`. Any new dependency that ships an install/postinstall script must be added to `allowBuilds` in `pnpm-workspace.yaml`, or `pnpm install` hard-fails with ERR_PNPM_IGNORED_BUILDS. npm is still used for `npm publish --provenance` (OIDC trusted publishing) and, during the A1 transition, the release.yml Electron build job (it moves to pnpm + hoisted linker in A2 — see `docs/refactor/pnpm-monorepo-migration-plan.zh.md`).
The test suite has two tiers: `pnpm run test` is the fast in-process unit tier for the development loop; `pnpm run test:cli` additionally runs the CCV_TEST_CLI-gated CLI/server integration suites (this is what CI runs). When committing code to GitHub, always run `pnpm run test:cli` first to ensure all tests pass; for new server-side scripts (any *.js under `server/**`), add corresponding unit tests in the test/ directory; update history.md accordingly, and update README.md with translation into all i18n supported language versions if needed.
Before publishing to npm, check if any new top-level files (e.g. `cli.js` bin entry, `findcc.js` fork-adapter, root shims `server.js` / `interceptor.js`) are missing from `package.json` `files` array; server-side code lives under `server/` which is already covered by the single `"server/"` entry.
When adding node_modules dependencies, be sure to distinguish between devDependencies and dependencies.
